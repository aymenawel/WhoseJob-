# WhoseJob? Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship WhoseJob?, a mobile web app that routes a VA-08 resident's local problem to the one office that fixes that exact spot and drafts the report they send themselves, live on a free URL by Sunday, Oct 25, 2026.

**Architecture:**
- A Next.js App Router app.
- Two server route handlers do the lookups that need a server:
  - `/api/geocode`: address to point.
  - `/api/resolve`: point to every jurisdiction check, run in parallel with fallbacks.
- A pure routing engine in the browser turns issue + checks + the team's rules file into one office and a reason.
- Screens follow the locked Guide Sign × Full-Screen Story direction.

**Tech Stack:** Next.js 16 (TypeScript, App Router), React 19, Leaflet 1.9 + OpenStreetMap tiles, Turf.js 7, exifr 7, Vitest 5 + Testing Library, Vercel Hobby.

**Spec:** `docs/superpowers/specs/2026-10-21-whosejob-design.md`. Also read:
- `PRODUCT.md`
- `docs/data-sources.md` (every endpoint, field and test point used below)
- `.impeccable/surfaces/src-app.md` (the visual direction contract)

## Global Constraints

- **Cost:** must cost nothing. No paid APIs, no keys that bill, no trial accounts. Stop and ask before adding anything that could ever cost money.
- **Census Geocoder:** always pass `benchmark=Public_AR_Current&vintage=ACS2025_Current`, which returns 119th Congress districts. Find the district key by searching for a key containing "Congressional".
- **Sending:** the app never sends anything on its own; the resident sends.
- **Photos:** never uploaded, never stored on a server.
- **Casework:** asks only for a short description. Never ask for Social Security numbers, case numbers, or medical details.
- **Rules and contacts:** live only in `src/data/routing-rules.json` and `src/data/offices.json`. No office name, phone, or URL in code.
- **Languages:** every user-facing string exists in English and Spanish (`src/lib/i18n/en.json`, `es.json`), including every rule's `why`.
- **Accessibility:**
  - WCAG 2.2 AA
  - touch targets ≥ 44 px
  - body text ≥ 18 px on phones
  - every icon paired with a word
  - every level of government shown by shape + color + word
  - `prefers-reduced-motion` respected
- **Visual direction:** follow `.impeccable/surfaces/src-app.md`.
  - Guide green `#00653b` with a white inset border for every answer.
  - Level markers: local = blue `#1b4f9c` rounded square; state = white "STATE" plate with black border; utility = yellow `#f7c600` diamond; federal = black-and-white shield.
  - Ground `#0c0f14`, Overpass font.
- **Sample data:** community map sample data is labeled "Sample data" wherever it appears.
- **Code comments:** short, explaining *why*, not *what*.
- **Commits:** small, with clear messages, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **An address the Census can't match** ("1600 Wilsn Blvd", or "Apt 4" included). Expect a plain message: "We couldn't find that address. Check the spelling, leave out apartment numbers, or drop a pin." Never a crash or a blank screen. Test in Task 3.
2. **A photo whose GPS is outside VA-08** (an old vacation photo). Expect "This spot is outside Virginia's 8th District" plus a "Move the pin" action, and no routing to a VA-08 office. Test in Task 6 (resolve) and Task 7 (engine).
3. **County and Dominion streetlights both within range** (common on Arlington streets). Expect the nearest light to decide. When the two nearest are within 3 m of each other, owner is `unknown`, which triggers the pole-tag question. Test in Task 5.
4. **Census timing out or erroring.** Expect locality and in-district status from the bundled polygons, a `census` entry in `fallbacks`, and the "using saved map data" note. Test in Task 6.
5. **A Spanish reader on any screen.** Expect no English leaking through: every i18n key, and every `why` in the rules file, has a non-empty Spanish string. Test in Task 7 (rules validation) and Task 9 (key parity).

## Shared types (defined in Task 2, used everywhere)

`src/lib/types.ts`:

```ts
export type LocalityId = "arlington" | "alexandria" | "falls-church" | "fairfax";
export type Level = "local" | "state" | "utility" | "federal";
export type RoadOwner = "state" | "county" | "city" | "private" | "unknown";
export type LightOwner = "dominion" | "novec" | "county" | "city" | "private" | "unknown";
export type IssueId =
  | "pothole" | "streetlight" | "signal" | "sign-traffic" | "sign-street-name"
  | "flooding" | "trash" | "abandoned-car" | "federal";
export type FallbackId = "census" | "road" | "streetlight";

export type Checks = {
  point: { lat: number; lon: number };
  district: { id: string; inCoverage: boolean } | null;      // id like "VA-08"
  locality: { id: LocalityId; name: string } | null;          // null outside our four
  road: { name: string; owner: RoadOwner; distanceM: number } | null;
  streetlight: { owner: LightOwner; poleId?: string; formUrl?: string; distanceM: number } | null;
  fallbacks: FallbackId[];
};

export type Localized = { en: string; es: string };

export type Route =
  | { kind: "routed"; office: string; level: Level; decidedBy: "road" | "streetlight" | "locality" | "federal";
      notOffice?: string; why: Localized; verified: string | null }
  | { kind: "out-of-coverage"; districtId: string | null }
  | { kind: "ask-pole-tag" };   // streetlight owner unknown: ask the resident
```

This extends the spec's `LightOwner` with `novec` and `private`, because Fairfax's NOVEC layer and Alexandria's `PVT` values exist in the data.
